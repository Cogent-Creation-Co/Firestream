# S6: generate /.github/dependabot.yml from Nix, with a drift and schema check

Epic: [[FIRE-049]]

## Scope

1. Add `bin/nix/firestream/github/dependabot.nix`. It is a `lib.evalModules` module with typed options for each `updates` entry: ecosystem, `directories`, schedule, groups, `open-pull-requests-limit` and labels.
2. Add the flake-module `nix/flake-modules/dependabot.nix`, and list it in `flake.nix`. Do not gate it to Linux.
3. **Derived entries.** Take every `sbomInputs` record ([[FIRE-051]]) that has a `repoDir` and `pinning = "lock"`, from all canonical containers. Map the ecosystem: uv to `uv`, npm and pnpm to `npm`, cargo to `cargo`.
   - Keep a directory only when `builtins.pathExists` finds the manifest that Dependabot needs (`pyproject.toml`, `package.json` or `Cargo.toml`).
   - This rule drops the upstream-tracked Supabase pnpm locks, `source-map-mappings` and the envoy `cargo-bazel` lock. No hand-written exclusion list is needed.
4. **Static entries** in the flake-module:
   - `github-actions` for `/`.
   - `cargo` for `/src/util`.
   - `npm` for `/src/app/firestream-docs` and `/src/app/firestream-homepage`.
   - `uv` for `/src/lib/python/etl-lib`, `/examples/airflow-dag-dependencies/dags-workspace`, `/examples/odoo-python-dependencies/python-workspace` and `/src/templates/odoo_python_workspace`.
   - `npm` for the 3 `examples/nextjs-*/app` directories.
5. **Groups:**
   - `odoo-18`: `odoo/18`, the odoo-python-dependencies example and the odoo template. `assertCompatibleLocks` fails when they disagree, so they must move together.
   - `nextjs`: the canonical app and the 3 examples.
   - All other entries: a minor/patch group for each directory.
6. Sort the entries and the directories so the output is deterministic.
7. Render with `pkgs.formats.yaml`. Put this one-line header in front of the YAML: `# WARNING: generated by make dependabot from nix/flake-modules/dependabot.nix; hand edits fail the firestream-dependabot-config check.`
8. The output is `packages.dependabot-config`.
9. `checks.firestream-dependabot-config` does two things:
   - It validates the generated file with `check-jsonschema --builtin-schema vendor.dependabot`. The schema ships with nixpkgs, so no network is needed.
   - It runs `cmp` against `../../.github/dependabot.yml`, the same pattern as `firestream-pnpm-lock-json` (`nix/flake-modules/checks.nix:329`).
10. Leave out `flake.lock` (the `nix` ecosystem), Helm and the legacy Dockerfiles. Nix does not use the versions that Dependabot would change there.

## Acceptance

- `nix build .#dependabot-config` gives a file that passes the schema validation.
- Edit `.github/dependabot.yml` by hand: the check fails.
- Add a new python-workspace container: its directory appears in the generated file with no edit to the generator.
